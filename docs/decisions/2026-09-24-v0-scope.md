# v0 scope and deferred features

Date: 2026-09-24

## Decision

v0 builds only the inclusion list in PRD section 3a. Within that scope:

- Claude Code and Codex are tested; pi is best-effort. A per-agent compatibility table records how
  each agent discovers instructions and skills, the tested version, and the last verification date.
- Supported platforms are macOS and Linux.
- `writing.formats` is a non-empty subset of docx and PDF (Typst), defaulting to both.
- The bibliography interface is one committed bibliography file. The add-paper skill adds entries
  from DOI metadata and does not retrieve full text.
- Delivery to readers without GitHub, public export of closed projects, and archival of milestone
  releases are manual.
- Template updates are applied through documented manual migration notes.
- Interfaces that implementation depends on are fixed in a normative appendix before implementation
  starts.

Everything else moves to PRD section 19a (Later) and out of normative text: companion repositories,
closed-to-public export, account-free delivery, archival automation, handoff hooks, Word comment
transfer, the licensed-data, human-subjects, LLM-measurement, timestamped analysis plan (formerly
preregistration), specifications, and ML-experiments modules, the weekly digest, reference-manager
synchronization and PDF retrieval, automated template updates, adoption mode, Windows, html output,
a devcontainer, and the website.

## Reason

A smaller v0 can be specified precisely and tested before the pilots. The deferred items are not
needed for a solo researcher or a small team to generate, review, and reproduce a paper, and several
need their own specifications (release contracts, evaluation protocols, merge behavior) before they
can be built correctly. Testing two agents and two platforms thoroughly is feasible; committing to
more as release gates is not. Every selectable output format has to be tested. A single committed
bibliography file means every configuration renders. A diff between template versions does not apply
cleanly to files that were filled in and then edited, so updates are migrated by hand. The analysis
plan module is renamed because a repository snapshot records a timestamped plan, and cannot show
that outcomes were unseen.

## Alternatives considered

- Keep the full draft scope in v0, or keep it with some features marked optional.
- Treat Claude Code, Codex, and pi equally as release gates; include Windows.
- Allow html as a selectable format.
- Offer several reference-manager modes, including an undecided mode.
- Apply updates by diffing the recorded and new template versions.
